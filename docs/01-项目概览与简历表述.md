# 项目概览与简历表述

## 1. 项目一句话定义

OmniSight 是一个面向前端应用的可观测性系统，覆盖错误监控、性能采集、用户行为回放、SourceMap 定位和告警通知。

它不是单纯的前端页面项目，而是一套从浏览器采集到服务端接入、再到可视化和告警的完整链路。

## 2. 解决的问题

前端线上问题通常有几个痛点：

1. 只能看到报错文案，看不到真实源码位置。
2. SDK 为了防止循环报错会做防抖，导致服务端统计失真。
3. 同一个错误到底影响了多少用户、多少会话，很容易统计错。
4. 告警消息经常只有一句错误文案，无法直接指导排查。
5. 控制台和服务端对同一字段的理解不一致，页面展示会出现错乱。

OmniSight 当前的核心价值，就是把这些口径和链路尽量做实。

## 3. 当前项目结构

这是一个 `pnpm workspace + turbo` 的 monorepo：

- `apps/sdk`：浏览器侧采集 SDK
- `apps/gateway`：NestJS 接入网关和查询/告警服务
- `apps/console`：React 控制台
- `packages/build-tools`：Vite 插件和 CLI Sourcemap 上传工具
- `packages/shared-types`：共享事件类型
- `packages/ui-components`：共享 UI 组件
- `infra/scripts/init.sql`：数据库初始化脚本

## 4. 当前已经落地的核心能力

1. 错误、API、Vitals、资源、行为、白屏、Replay 采集。
2. SDK 会话内错误防抖，并通过 `occurrences` 恢复真实错误次数。
3. Gateway 按 `fingerprint` 聚合错误，按 `SUM(occurrences)` 统计真实次数。
4. `affectedUsers` 优先按 `userId`，没有时退化到 `session_id`。
5. Replay 和错误详情可关联。
6. SourceMap 已支持上传、版本匹配、源码位置还原、源码片段提取。
7. 错误详情已支持“主错误单点摘要 + 多帧 stack remap”。
8. 飞书告警已支持带上源码位置、源码片段、Git 信息和 Console deeplink。
9. 已提供官方接入自动化：Vite 插件 + CLI Sourcemap 上传工具。

## 5. 简历上的推荐表述

### 精简版

负责实现一套前端可观测性系统，覆盖浏览器 SDK 采集、NestJS 接入网关、可视化控制台、用户回放、SourceMap 定位与飞书告警，重点解决错误去重、防抖导致的统计失真、影响人数口径统一和线上源码定位问题。

### 强化版

主导一个基于 Monorepo 的前端可观测性平台建设，拆分为浏览器 SDK、NestJS Gateway、React Console 三个核心应用。围绕错误监控实现了会话内防抖与 `occurrences` 次数恢复机制，修复了服务端按指纹粗粒度去重导致的统计失真问题；同时打通构建阶段自动注入 `release`、自动上传 SourceMap、服务端按 `appId + release + artifact` 精确反查源码位置、错误详情多帧 stack remap，以及飞书告警附带源码上下文与 Console deeplink 的完整链路。

## 6. 面试时可以怎么开场

可以这样讲：

> 这个项目我主要做的是一条完整的数据链路，不只是页面。浏览器侧 SDK 负责采集错误、接口、性能和回放；服务端 Gateway 负责接入、异步消费、聚合查询和告警；Console 负责把这些数据展示出来。这个项目里我重点解决了三个问题：第一，客户端防抖和服务端真实统计之间的冲突；第二，错误详情和告警里如何真正定位到源码；第三，前后端字段口径不一致导致的展示错误。

## 7. 不要夸大的点

下面这些内容不能说得比代码更满：

1. 现在已经支持常见浏览器栈的多帧 remap，但不是所有运行时栈格式的“完整重写调试器”。
2. 自动接入当前正式提供的是 Vite 插件 + CLI；Webpack 仍走 CLI 方案。
3. Sourcemap 存储目前是本地文件系统，不是对象存储。
4. WebSocket 实时告警推送没有真正落地。
5. 资源性能聚合和 UA/Geo 富化还不是完整实现。
