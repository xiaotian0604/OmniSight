# 当前能力、边界与演进方向

## 1. 当前已经做成的能力

### 可用

1. 浏览器多类型事件采集。
2. session 级错误防抖和 `occurrences` 真实次数恢复。
3. 服务端错误聚合和影响人数统计。
4. Replay 上传、列表和播放器。
5. 错误详情与 replay 关联。
6. SourceMap 上传、查询、主错误单点源码还原和多帧 stack remap。
7. 飞书告警附带源码位置、源码片段、Git 信息和 Console deeplink。
8. Console 错误详情页展示源码上下文和结构化映射栈。
9. 官方接入自动化：Vite 插件 + CLI Sourcemap uploader。

## 2. 初级版本或部分完成的能力

### SourceMap

当前状态：

- 已支持上传和反查
- 已支持 release 精确匹配
- 已支持代码片段
- 已支持常见浏览器栈的多帧 remap
- 但还不是所有运行时格式的完整调试器级还原

### 性能分析

当前状态：

- API 和 Vitals 查询可用
- 资源维度还不完整

### 告警

当前状态：

- 飞书可用
- 冷却位逻辑可用
- 高频统计口径已修正
- 已支持错误详情 / Replay deeplink
- 但没有多渠道完整落地

## 3. 明确还没实现的能力

1. Webpack 官方插件（当前正式提供的是 Vite 插件 + CLI）
2. SourceMap 对象存储
3. WebSocket 实时告警
4. UA / Geo enrich 真正落地
5. 源码片段权限控制与脱敏

## 4. 面试时应该怎么诚实表达

### 可以说已经做了

- “已经打通了构建期自动注入 release、SourceMap 上传、错误详情多帧源码定位和飞书告警 deeplink 的链路。”
- “已经修复了客户端防抖导致服务端统计失真的问题，用 `occurrences` 恢复真实次数。”
- “已经把错误次数、影响人数和告警链路的统计口径统一起来。”

### 不要说得过满

- “支持所有栈格式、所有运行时场景下的完整调试器级源码还原。”
- “有完善的实时告警系统。”
- “有生产级对象存储和发布插件。”

## 5. 后续演进建议

### 第一阶段

1. 做 Webpack 插件
2. 做对象存储版 Sourcemap 管理
3. 做更完整的接入模板和示例项目

### 第二阶段

1. 做更精确的资产映射（manifest 驱动）
2. 做源码片段权限控制
3. 做多渠道告警

### 第三阶段

1. 做 WebSocket 实时推送
2. 做告警规则配置化
3. 做资源性能与用户行为分析深化
